This package prepares one fixed nominal diagnostic after D155 revision2 approved
preparation of the v3 probe. It does not reset that decision's consumed review
budget. Root will commission a separate composition decision. No actual probe,
guard, namespace, mount, semaphore, compiler or proof ran here. The source author

## Minimal composition and preserved control outcome

The collector is a v4 copy with the exact v3 probe path/pin and fresh v5 output
suffix. Every inherited function except parent is AST-identical; parent gains
only the new output suffix, separate nominal diagnostic receipt call and receipt
reference. Its original positive/negative checks and terminal return expression
are unchanged. New helper functions interpret retained diagnostics separately.
No selector, mount topology, acceptance predicate, semaphore or cleanup repair is
included. Existing dispatcher modes remain present, with no launch authority for
any mode other than this separately admitted fixed nominal ipc-probe diagnostic.

The guard is an exact four-literal-only copy of ipc_capacity_guard_v1.py: new JOB,
LOG, expected inner output and collector filename. No guard logic changed. It does
not enforce collector/probe source hashes itself. Root's exact prelaunch and
terminal source/tool/runtime readbacks remain required. Old occupied output/log
paths are never reused. Source copying does not inherit an execution approval.

For a repeated original private-identity predicate failure, the preserved outcomes
are probe exit2, inside collector exit0 after successful retention/restoration,
parent collector exit1, and guard exit1 after terminal-scope readback. The optional
result file may be absent. The new diagnostic never converts that failure into a
successful control. An unexpected parent0 also supplies no mechanism or product
qualification: six-case qualification and independent raw readback remain open.

## Separate diagnostic interpretation

mount_diagnostic reads archived full tool.stdout, not an optional result file as
its primary observation. It checks the complete archive/restore receipt, archive
size/hash and tool receipt, then extracts exactly one bounded regular stdout tar
member and checks its inventory size/hash. It parses ASCII JSON with duplicate
keys and nonfinite constants rejected, under the inherited stdout byte ceiling.
The archive is not opened until its declared size and identity have been checked.
These checks are conditional on the authentic pinned execution/OS receipts; they
are not cryptographic authentication of a malicious replacement receipt chain.

The consumer bounds evidence at3072 bytes and validates integer types explicitly
(bool is not an integer counter/index), final retained/omitted counts, completeness,
ordered unique row indices, raw record shape and decimal row IDs. Only a complete
candidate roster permits recomputing the declared LF-joined candidate hash or
claiming a unique global FD-row join. Incomplete evidence retains its declared
hash but reports candidate_digest_verified=false and fd_join=UNPROVEN. The hash is
not claimed verified from a retained prefix.

For a complete roster the consumer independently reconstructs the original
first-longest/first-tie selection and checks its selected row/index/ID hash and
tie metadata against the report. It verifies the single decimal opened-FD ID
against raw fdinfo and requires exactly one retained row with that ID. ID999,
duplicate matching IDs, missing/malformed evidence and forged accounting retain
UNPROVEN interpretation. A successful join is observational only; it does not
replace the selected row or change any original mount predicate. The separately
saved mount-diagnostic-check.json always says mechanism_qualified=false,
proof_credit=false and phase_acceptance=false.

Optional tmp/private-ipc-probe.json is independently bounded and checked against
stdout when present. ABSENT is allowed for an early refusal. DIFFERENT is an
explicit UNPROVEN interpretation with the actual tool exit preserved. An earlier
success receipt cannot override failed final stdout or nonzero tool termination.
Pretty result-file JSON and compact stdout have separate inherited8192-byte
checks; pretty JSON can overflow while compact stdout fits. Receipt writing can
precede final tmp-FD close, so a later close failure can invalidate an earlier
result receipt. This package does not change those lifecycle boundaries.
