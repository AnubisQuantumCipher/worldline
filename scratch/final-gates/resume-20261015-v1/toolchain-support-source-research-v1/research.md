# Public toolchain source research

**UNVERIFIED:** a newer matching GNAT/GNATprove toolchain with automatic full-value/`Old` retirement is not established. No installation candidate is proposed. This is bounded source research, not a proof run or formal review.

**MEASURED source identities:** AdaCore `spark2014` master `03075d376653e022ceb3b7e303fc368fb0d28fc4` and FSF `b9410c6ed36d4e69a6c4d31e152fa8facaf0235c`. HTTPS response bodies, request URLs, UTC times and SHA-256 identities are retained beside `research.json`. Exact source locators and the bounded spelling scan are recorded there.

The inspected marking paths reject `Ada.Finalization.Controlled`; that does not establish rejection of the separate `Finalizable` aspect. The more relevant observed condition is the expression translator: allocating calls with allocated parts inside executable assertions produce a static failed resource-leak verification condition. That condition has no `Finalizable` exemption. Both branches also retain end-of-scope leak checks. The `Finalization_Actions` routine translates existing `Finally_Statements`, otherwise handling borrows and leak checks. Explicit finally-section translation is not evidence that automatically generated `Adjust`/`Finalize` calls, implicit `Old` values and exception cleanup are modeled. [Pinned master translator](https://github.com/AdaCore/spark2014/blob/03075d376653e022ceb3b7e303fc368fb0d28fc4/src/why/gnat2why-expr.adb), [pinned FSF translator](https://github.com/AdaCore/spark2014/blob/b9410c6ed36d4e69a6c4d31e152fa8facaf0235c/src/why/gnat2why-expr.adb).

The bounded inspected files contain no `Finalizable` spelling. This does **not** prove global absence: the compiler front end was not fetched or executed, and it may lower language constructs before these paths. No explicit upstream statement that the entire feature is unimplemented was located in the inspected files. The retained source provides no positive implementation evidence sufficient to justify a toolchain upgrade as the repair.

The root-retained release page lists `gnatprove-16.1.0-1`, the unstable July `gnatprove-16.0.0-20260714` snapshot, and the later unstable compiler `gnat-16.1.1-20261010`. Their release bodies do not establish this feature or a matching newer pair. Asset names, published dates and API-provided digest metadata are recorded; no archives were downloaded. [Prover snapshot](https://github.com/alire-project/GNAT-FSF-builds/releases/tag/gnatprove-16.0.0-snapshot), [compiler snapshot](https://github.com/alire-project/GNAT-FSF-builds/releases/tag/gnat-16.1.1-snapshot).

AdaCore's retained README requires a matching compiler and matching front-end sources, warns that master follows development GNAT, and directs public compiler users to FSF branches. A compiler version change alone is not a matching prover implementation. The initial `/AdaCore/spark2014/releases/latest` HTTP 404 is retained as an endpoint failure, not universal release absence. [Official README](https://github.com/AdaCore/spark2014#building-spark).

The original installed-toolchain reproducer failures stay in force.
